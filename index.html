Intelligent First Response

AI-generated first responses and customer handling notes for support tickets

• Problem: Engineers spent time on the first read of every ticket, decoding the error and hunting SharePoint for customer handling instructions.

• Action: Pitched surfacing handling notes in Zendesk, defined 18 error categories and the AI response format, and worked with engineering on the AWS architecture.

Past Ticket Analysis

RAG over resolved tickets, so analysis reflects how engineers actually solved similar issues

• Problem: Generic AI first responses didn't reflect how engineers had actually solved similar tickets before.

• Action: Analyzed 22K+ resolved tickets into reusable "signatures" and built a RAG-powered Zendesk side-app with cited similar tickets and a chat interface.

• Result: Live since July 2026, with ~58K tickets processed, a 98.6% response rate, and an 80.6% acceptance rate, and signatures consolidated from 503 to 374 to push that higher.

Stack: Python, Claude Sonnet/Haiku 4.5, Titan Text Embeddings v2, OpenSearch (Vector Store), AWS serverless stack, Zendesk App Framework, LangChain, FastAPI

Ticket Merge/Link Agent

Automating duplicate ticket merging to cut wasted compute and engineer effort

• Problem: About 48% of tickets are manually merged because they share a root cause, wasting engineer effort and LLM tokens.

• Action: Spent 3 months working with engineers across 207 customers to write a 7-revision SOP, then designed an agent that merges only on an exact "golden match".

• Result: Targeting automation of 80% of manual merges, currently in testing.

Stack: Python, AWS (API Gateway, Lambda, DynamoDB, S3, SQS, CloudWatch, Bedrock, EventBridge, CodePipeline, CodeBuild, ECS Fargate), Zendesk, LangChain, Blue-Green deployment
